# Competition map: tower height and repeating USB cycles

The shared map is generated by `src/dream_hackathon/demo_strategy.py`. A fresh
controller loads it automatically. In an existing saved installation, click
**Demo strategy** in the Orchestration toolbar, then Save to adopt it. The existing
saved map is not silently replaced. The integrated implementation is published on `main`; the tested controller
is deployed on NUC-1. Saved maps remain installation-specific.

`configs/demo_strategy.json` is an exported, importable copy. Refresh it after
changing the builder with `PYTHONPATH=src python -m dream_hackathon.demo_strategy
configs/demo_strategy.json`. A teammate can edit that JSON and Import it directly
without changing the builder or scheduler.

## Strategy

Go starts a 300-second match clock and the recorded right-arm pull-all attempt.
After every attempt, an automatic hub inspection checks for a known removal.
Unknown or zero removal retries the recorded attempt. A known removal of at least
one cable opens the gate into two parallel branches:

* **Left:** inspect the tower, rebuild if collapsed, otherwise stack one more
  block until the editable cap (initially seven). At/above the cap, keep observing
  without moving. From 240 seconds onward, hold when the standing count is
  strictly greater than five. Five can become six; six and seven hold. Collapse
  returns to rebuilding even during the final minute. Unknown observations wait
  for a new inspection. The clock never resets during retries or restacking.
* **Right:** use the trained unplug policy until all four original hub positions
  are clear. Then repeat recorded insertion attempts until fully inserted AND
  the gripper is released. Return to the unplug-policy start pose, call the
  unplug policy until the cable is out, resting on the table, and released, then
  start insertion again. There are no ball operations.

At 300 seconds the configured Finish operation cancels remaining graph routing,
owned episode playback, scripts, and active Dream playback. It does not switch
off motor torque. The clock is an explicit editable part of this match map, not
a hidden runtime cutoff.

The team reports that the judges approved repeated plug/release/unplug/table/
release scoring. The supplied rubric v4 instead says an unplugged cable may not
be plugged back in, and lists up to four loose-cable insertions. The map follows
the team's reported judge ruling. This difference is also recorded in its notes.
No additional score-per-cycle claim is inferred from the PDF.

## Replaceable bindings

Every operation node has its own **Target arms** setting. There is one shared
map, with no Left/Right/Both graph selector. Click a block to open its sidebar;
close the sidebar to reclaim the full canvas. Save/load/import/export and Add
block are in the compact toolbar. There is no bottom Live run panel.

The map's top-level `bindings` registry decouples the operations from the wiring.
All bindings start as **explicit dummies**, per the team's request. Dummies do
not send motion commands or call a provider. Dummy observers return `known:false`;
they do not fabricate a successful gate. Thus an unconfigured run repeats the
dummy pull/inspection branch until its configured match clock ends.

| Binding | Intended implementation | Output / responsibility |
| --- | --- | --- |
| `pull_all` | Recorded episode | One complete pull-all attempt |
| `plug_usb` | Recorded episode | Insert and release the plug |
| `return_usb_start` | Recorded episode | Move to the unplug policy's start pose |
| `unplug_policy` | Dream API | Unplug, place on table, release; used in clearing and repeat cycles |
| `stack_next` | Dream API | Place one more block and release |
| `rebuild` | Dream API | Recover fallen blocks and rebuild a base |
| `verify_usb` | Automatic VLM/detector adapter | USB scene contract below |
| `verify_tower` | Automatic VLM/detector adapter | Tower scene contract below |

To connect one, click a block using that binding. **Use planned implementation**
replaces its dummy with the provided `replaceWith` configuration. Fill in the
episode path/checkpoint/provider settings, then Save. Editing a shared binding
changes every block referencing it. Alternatively select another Execute kind
(script, HTTP, VLM, or Dream) without changing any edge. Target arms remain on
the individual node, independent of the shared binding implementation.

For an HTTP verifier set **Output object path** to `body`, so its JSON response
becomes the flat scene contract expected by the conditions. A script printing a
JSON scene can use `stdout`. Nested provider replies can select a dot path to a
JSON object or JSON-encoded text. This keeps provider response envelopes out of
the graph wiring. Blank keeps the operation's standard result object.

Episode plans are JSON objects with `targets_file` pointing to a relative JSONL
file. Each row contains `t` (seconds), `q` (six joint radians), and `grip`.
Playback uses the node's selected arm rather than a stale `target_url` in the
plan. If the plan declares `initial_approach_max_joint_speed_rad_s`, that explicit
initial approach setting is retained. Otherwise the stored trajectory is played
directly. A single-arm plan targets Left or Right. More complex/bimanual recorded
programs can use the Script or HTTP operation instead.

Scripts receive `ORCHESTRATION_ARMS` and `ORCHESTRATION_RUN_ID` in their environment.
HTTP operations send `X-Orchestration-Arms`; the API adapter must use that target
or explicitly encode the target in its own URL/body. Dream uses the chosen arm
worker. Verifiers can use scene or wrist cameras independently of their target.

## Scene contracts

USB results:

```json
{"known":true,"unplugged_count":1,"plugged_count":3,
 "gripper_released":true,"cable_on_table":true,"fully_inserted":false}
```

Counts refer to the four original hub positions: `unplugged_count = 4 - occupied
ports`. Do not count unrelated loose cables as removals. `known:false` handles
an obscured/indeterminate scene. The first-removal gate and later conditions read
the most recent inspection node's result, rather than an old latched signal.

Tower results:

```json
{"known":true,"block_count":6,"collapsed":false,"standing_free":true}
```

`block_count` is the current standing tower, not cumulative placement attempts.
After collapse report the actual new state, so rebuilding does not inherit an old
height. A vision adapter can combine deterministic measurements with VLM scene
judgment and return this contract. API replies can also be used directly through
a small adapter that returns these fields. Built-in VLM inspection supports a
custom structured schema; the intended templates include the schema and question.
Provider accuracy still needs testing on actual camera images. A single image
cannot establish a three-second free-standing interval; continuous timing and
calibrated height remain the measurement adapter's responsibility for scoring.

## Team / agent handoff

1. Keep stable node IDs and binding names when changing an implementation.
2. Change the sidebar settings or exported JSON; no flow-runtime changes are
   needed to record a new episode or choose a trained checkpoint.
3. Change shared limits with **Map settings**: `maxBlocks`, `lateAtSeconds`,
   `lateHoldAbove`, `runSeconds`, and `pollSeconds`. The cap of seven is a strategy
   setting, not a claim that the rubric specifies seven blocks.
4. Add a new binding with a configuration object and reference it from an action
   node using `{"operation":"binding","binding":"name","selection":"left"}`.
5. For code changes to the strategy, update `competition_graph()` and its tests.
   Exported JSON is a portable editable copy, not a separate required runtime.
6. Run `PYTHONPATH=src python -m pytest tests/test_demo_strategy.py
   tests/test_orchestration.py tests/test_demo_vlm.py -q` before handing off.

Tests simulate first-attempt failure, gate opening, concurrent left/right work,
collapse/restacking, the late-count rule, USB insertion/unplug retries, and the
configured end time. They do not operate a real robot or claim trained policies
are recorded or validated.
